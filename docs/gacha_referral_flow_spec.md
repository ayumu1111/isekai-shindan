# ガチャ本体への送客導線 設計

対象：診断結果ページ → 異世界転生ガチャ本体（別ドメイン）
関連：`answer_screen_ui_spec.md`／`ogp_image_spec.md`／結果ページモックアップ（`results_page_mockup.html`）

---

## 1. 前提

- 診断とガチャ本体は**別ドメイン**で運用予定
- ガチャ側のIndexedDBに直接書き込む等の連携はできないため、URLパラメータのみで受け渡す
- インセンティブ（診断完了でガチャ+1回等）は**付けない**。単なるリンク誘導とする

## 2. 設置箇所

- 結果ページ最下部のCTA（メイン導線）
  - 「結果をシェアする」ボタンの下に「ガチャで転生キャラを引いてみる」ボタンを配置（結果ページモックアップに実装済み）
- それ以外の場所への追加設置は行わない（導線を絞り、離脱ポイントを増やさない）

## 3. メッセージング方針

診断結果でマッピングされたキャラと、実際のガチャで引けるキャラは**一致しない前提**（完全ランダム抽選、OR等は超低確率）。「診断結果のキャラを引こう」という煽りは期待外れを生むため避け、**軽い接続**に留める。

- 採用：「異世界にはこんなキャラも転生しています。ガチャで運試ししてみませんか？」
- 不採用：「診断結果のキャラをガチャで手に入れよう」（実質不可能な場合があり誠実でない）

## 4. リンク設計（計測用UTM）

別ドメインのため、診断経由の流入をUTMパラメータで計測する。

```
https://<ガチャのドメイン>/?utm_source=diagnosis&utm_medium=result_page&utm_campaign=personality_test
```

| パラメータ | 値 | 用途 |
|---|---|---|
| `utm_source` | `diagnosis` | 診断サイトからの流入と識別 |
| `utm_medium` | `result_page` | 結果ページのCTA経由と識別 |
| `utm_campaign` | `personality_test` | 将来、結果ページ以外の流入経路（OGP画像内リンク等）を追加した場合に区別するため予約 |

診断結果キャラをクエリに含める連携（`ref_char`等）は**見送り**。
